# MEMORY.md — 记忆、画像与上下文压缩规范

## 隔离

- 每位玩家由 UUID 优先、玩家名兜底生成独立身份键，并拥有独立 `USER.md`。
- 处理消息时只加载当前玩家的 `USER.md`、专属事实、专属对话摘要以及必要的公共游戏事件；不得把其他玩家画像拼入当前上下文。
- 改名但 UUID 相同仍使用同一画像；没有 UUID 时按规范化玩家名创建，之后获得 UUID 可迁移关联。

## 写入

- `remember` 只记录玩家明确表达、未来仍有帮助的稳定事实，如称呼、偏好、长期目标、协作习惯和明确禁忌。
- 不保存密码、API Key、令牌、登录命令、真实地址、本地路径、一次性坐标或未经确认的猜测。
- 新玩家首次发来有效指令时立即创建对应 `USER.md`；压缩时更新其中的自动画像区。
- 游戏经验与玩家画像分开：玩法失败写经验/行为补丁，玩家兴趣和交流偏好写该玩家 `USER.md`。

## 召回

- 优先级：当前指令 > 最近相关事件 > 当前玩家画像 > 当前玩家摘要 > 已验证经验 > 全局摘要。
- 旧信息与玩家最新明确表达冲突时，以最新明确表达为准，并在后续压缩中更新摘要。
- 不因画像推测权限；玩家偏好不能覆盖 `rules.md` 或本地硬策略。

## 自动压缩

- 系统按字符预算估算即将提交给模型的上下文。达到配置比例时，由当前模型把较旧事件压缩为“玩家对话摘要”和“全局游戏摘要”。
- 压缩必须保留：未完成承诺、稳定偏好、重要共同经历、已验证事实、长期任务、纠错结论和安全相关信息。
- 压缩必须丢弃：重复寒暄、已经完成且无长期价值的细节、冗余日志、动作参数回显和秘密替代符周围的无用内容。
- 最近事件按配置数量原样保留；被压缩事件从活动事件窗口移除，但摘要、原子文件备份和压缩时间会留下。
- 摘要不得发明事实。证据不确定时明确写“未确认”，而不是补全猜测。
