## 7. 中国大陆网络兼容基线

所有方案设计和代码评审都必须逐项考虑：

1. **依赖获取**：提供中国大陆可访问的包管理器镜像或离线安装方式；镜像地址应可配置，不硬编码为唯一来源。
2. **容器镜像**：如使用容器，提供中国大陆可获取的基础镜像方案或镜像导入说明。
3. **AI 服务**：抽象服务提供方和 API Base URL，至少允许配置中国大陆可用的模型服务；不得将单一境外服务写死在核心逻辑中。
4. **Minecraft 资源**：说明游戏版本、认证、服务端、模组或协议库所需的下载源及替代方案。
5. **运行时请求**：记录所有外部域名、用途、超时、重试、缓存和不可达时的行为。
6. **时间与编码**：默认兼容 UTF-8、中文路径和 Asia/Shanghai 时区；跨平台路径不得写死为开发机绝对路径。
7. **文档可执行性**：安装与启动教程必须包含无特殊代理条件下的路线。
8. **验证**：发布前在中国大陆常规网络环境完成从干净环境安装到核心功能运行的测试，并记录日期、环境和结果。

目前这些要求尚未通过实际运行验证，因为项目还没有实现代码。后续 Agent 不得把“设计上可配置”等同于“已经在中国大陆验证通过”。

- 决定：核心智能体不直接依赖某一家模型 SDK，也不直接绑定 Mineflayer 或原生 Fabric 实现。模型调用和 Minecraft 控制均通过稳定接口接入。

### ADR-004：记忆与经验必须是可迁移的独立持久化边界

- 日期：2026-08-03
- 状态：已采纳，具体文件格式待原型决定
- 决定：长期记忆统一保存为一个文件；经验学习另存为一个文件。两者都必须支持原子写入、版本号、备份、校验、导出/导入和跨运行位置恢复。
- 原因：用户要求 Bot 在下线、重启、重装或程序误删后保留记忆，并要求独立经验文件避免重复犯错。
- 影响：日志、模型缓存和临时状态不得冒充记忆；玩家身份、摘要和重要事件必须进入正式持久化结构。

## 10. 候选模块边界（尚未生成代码）

2. `minecraft-adapter`：连接、聊天、感知和动作接口；候选实现为 PrismarineJS/Mineflayer 与原生 Fabric 客户端。

## 11. 2026-08-03 初步资料核对

以下结论用于选型，不代表已经通过目标服务器实测：

- Fabric Meta API 返回 Minecraft `26.2` 的稳定 Loader `0.19.3`，与用户给出的版本一致。
- Modrinth API 返回 EasyAuth `3.4.4` 的 `26.2` Fabric 构建；EasyAuth 会限制未认证玩家移动、交互和多数命令，因此认证状态机必须先于正常行为启动。
- Modrinth API 返回 Simple Voice Chat `fabric-2.6.20+26.2`；其官方项目还提供 API，但语音通常使用独立 UDP 通道，部署时必须检查端口和中国大陆服务器网络策略。
- Mineflayer 官方 README 当前列出的支持范围主要到 `1.21.11`。其公开问题显示对 `26.1.2` 也曾需要新增协议数据，因此不能假设 `26.2` 可直接工作。
- OpenAI 官方模型指南确认 GPT-5.6 模型标识包括 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`，`gpt-5.6` 别名指向 Sol；Responses API 的推理强度包含 `none/low/medium/high/xhigh/max`。实现时仍应通过配置而不是硬编码唯一模型。
- DeepSeek 官方 API 在当前日期列出 `deepseek-v4-pro` 和 `deepseek-v4-flash`，支持思考开关与 `high/max` 推理强度；旧 `deepseek-chat`、`deepseek-reasoner` 已到官方公告的停用日期之后，不能作为“全系列支持”的唯一硬编码入口。适配器应支持模型列表查询和显式配置。
- 火山引擎官方资料能确认方舟 API Key 与 OpenAI SDK 兼容调用路线，但本次检索未获得足以确认豆包 Seed 2.1 Pro 精确模型 ID/推理强度参数的官方页面。实现前必须从用户方舟控制台或最新官方文档核对，不能猜测模型 ID。

## 12. 安全与行为细节

- EasyAuth 密码、API Key、Microsoft 登录令牌只能来自环境变量、系统密钥库或未跟踪的本地秘密文件。
- `/login <密码>` 所在日志必须整体脱敏；不得把命令原文发送给 LLM、写入记忆/经验或异常报告。
- 玩家身份优先使用服务器提供的 UUID；离线模式 UUID 或名称变化时必须有可审计的合并流程，禁止自动错误合并。
- 自主发展前必须执行选址策略，避开已有建筑、容器、农田、红石和玩家声明区域。无法判断归属时默认不破坏。
- 自卫只能在可配置的短时间窗口内针对实际攻击者，威胁解除后停止；不得追击无关玩家或扩大破坏。
- 主动聊天必须限频、可关闭，并避免泄露系统提示、记忆文件、凭据、服务器地址或其他玩家隐私。
- 从 GitHub 下载的项目或代码在使用前必须记录来源提交、许可证并进行安全审查；不能直接运行不明脚本。

## 13. 未决问题与下一步

首个编码里程碑应为“连接可行性探针”，在此之前或过程中需确认：

1. 目标服务器地址和端口（敏感时仅放本地配置，不写入 Git）。
2. `server.properties` 的 `online-mode` 实际值；用户原文“无在线认证模式（正版认证）”存在冲突。
3. 服务器完整模组清单，以及哪些模组要求客户端安装。
4. 测试 Bot 名称、EasyAuth 是否已注册，以及登录密码如何安全注入。
5. 是否可以建立本地同版本 Fabric 测试服，避免直接在正式服做破坏性协议实验。
6. 首选实现语言；应根据 `26.2` 连接探针结果决定 Node.js PrismarineJS 还是 Java/Fabric 客户端路线。
7. 第一个启用的模型供应商和用户已具备的 API 凭据；默认优先选择中国大陆稳定可访问的 DeepSeek 或火山方舟进行端到端测试。
8. 许可证、测试策略、发布形式和目标操作系统。

下一步推荐动作：先搭建不含真实凭据的模块骨架、配置 schema 和连接探针；在获得目标服务器信息后运行只读/低风险连接测试，记录握手与断线包，再冻结 Minecraft 适配器方案。

在用户没有给出相关决定前，不要把猜测描述成最终架构；可以在明确标注假设的前提下提出方案。
