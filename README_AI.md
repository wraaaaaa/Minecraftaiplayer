## 6. Git 提交与推送手册

### 常规同步

```bash
git status --short --branch
git pull --ff-only origin main
```

如果存在用户未提交的改动，不要擅自丢弃、覆盖、暂存或提交；先区分本次改动与既有改动。

### 提交

```bash
git diff --check
git diff
git add <本次明确修改的文件>
git commit -m "<准确描述改动的消息>"
```

提交前必须确认 `README.md` 和 `README_AI.md` 都已按本次改动更新。

### 推送

```bash
git push origin main
git status --short --branch
```

成功标准：推送成功，且状态显示本地 `main` 与 `origin/main` 没有领先、落后或未提交改动。

### 作者身份

本机最初未设置 Git 作者身份。若再次遇到 `Author identity unknown`，只在本仓库配置，避免擅自修改用户全局设置：

```bash
git config user.name "wraaaaaa"
git config user.email "310438732+wraaaaaa@users.noreply.github.com"
```

该隐私邮箱根据 GitHub 公开账号 ID `310438732` 与账号名 `wraaaaaa` 生成。若仓库所有者或提交账号改变，必须先向用户确认新的作者身份，并同步更新本节。

### 禁止事项

- 不使用强制推送覆盖远端，除非用户明确授权且已说明风险。
- 不使用 `git reset --hard`、删除分支或改写历史来处理不明改动。
- 不提交凭据、日志中的敏感信息、构建缓存或无必要的大型二进制文件。
- 不在远端 URL 中保存访问令牌。

## 7. 中国大陆网络兼容基线

所有方案设计和代码评审都必须逐项考虑：

1. **依赖获取**：提供中国大陆可访问的包管理器镜像或离线安装方式；镜像地址应可配置，不硬编码为唯一来源。
2. **容器镜像**：如使用容器，提供中国大陆可获取的基础镜像方案或镜像导入说明。
3. **AI 服务**：抽象服务提供方和 API Base URL，至少允许配置中国大陆可用的模型服务；不得将单一境外服务写死在核心逻辑中。
4. **Minecraft 资源**：说明游戏版本、认证、服务端、模组或协议库所需的下载源及替代方案。
5. **运行时请求**：记录所有外部域名、用途、超时、重试、缓存和不可达时的行为。
6. **时间与编码**：默认兼容 UTF-8、中文路径和 Asia/Shanghai 时区；跨平台路径不得写死为开发机绝对路径。
7. **文档可执行性**：安装与启动教程必须包含无特殊代理条件下的路线。
8. **验证**：发布前在中国大陆常规网络环境完成从干净环境安装到核心功能运行的测试，并记录日期、环境和结果。

目前这些要求尚未通过实际运行验证，因为项目还没有实现代码。后续 Agent 不得把“设计上可配置”等同于“已经在中国大陆验证通过”。
